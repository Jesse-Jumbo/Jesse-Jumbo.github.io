FOVY

從早期前端到後端服務

早期以 Next.js 製作前端並部署於 Render；專案改採 monorepo 與微服務後，投入 Django 認證、文件服務與跨服務整合。

  • Next.js
  • Render
  • Django
  • gRPC
  • RabbitMQ
  • Docker
專案細節

問題與情境

產品從早期介面逐步發展為多服務系統，需要在不同階段處理前端呈現、認證、文件流程與服務間的責任邊界。

設計與實作

  • 早期使用 Next.js 開發前端，並架設於 Render。
  • 在專案採用 monorepo 與微服務架構後，負責 Auth 與 Document 服務。
  • 以 Django、gRPC 與 RabbitMQ 處理服務及通訊，搭配 Docker 容器環境。

這個專案的重點

從早期前端實作累積產品理解，再將工作延伸到後端服務與整合。網站可公開瀏覽，原始碼未公開。

02 / AI 應用・公開原型2025

歷史資料 AI 問答

讓回答保留資料來源

整合資料匯入、向量檢索與 AI 回答，讓使用者能從回覆追溯到相關資料來源。

  • Python
  • FastAPI
  • SQLite
  • React
專案細節

問題與情境

把文字資料交給 AI 之前，需要先處理資料匯入、檢索與來源關係，讓回答有可查驗的依據。

設計與實作

  • 以 FastAPI 提供服務，SQLite 儲存文件與來源欄位。
  • 結合向量檢索，將相關資料與來源標示整理成回答所需的上下文。
  • 串接 React 介面，顯示回答、來源與資料管理狀態。

這個專案的重點

檢索與生成各有責任；可追溯的來源，是使用者判斷回答是否可信的基礎。

這個專案的重點

06 / 特教遊戲開發・模板設計・團隊帶領2022–2023

PTWA 特教遊戲

約 27 款遊戲、共用模板與協作開發

開發約 27 款特教遊戲與可延伸的模板，並帶領兩位成大同學一起開發，把教師的教學需求轉成容易操作的互動練習。

  • JavaScript
  • HTML
  • CSS
  • Canvas
專案細節

問題與情境

不同教案涵蓋數字、分數、時間、容量與重量等概念。操作、提示與回饋要配合學生能力，開發方式也要能支援多款遊戲持續擴充。

設計與實作

  • 以 JavaScript、HTML、CSS 與 Canvas 實作連連看、拖拉配對、點選判斷等互動。
  • 整理數字與手勢配對、三年級數學教案等需求，歸納共通的互動方式並開發遊戲模板。
  • 運用 AI 工具協助模板歸納與程式實作，再依遊戲需求驗證、修改。
  • 帶領兩位成大同學共同開發，將教學需求與共用模板帶入協作。

這個專案的重點

把重複的開發工作整理成模板，讓團隊能延伸更多教案；每一款遊戲仍需回到學生的操作與理解方式。
